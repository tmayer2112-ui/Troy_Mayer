# Orthosis EMG decoder: what the v1 and v2 boards can actually decode

The orthosis has two EMG front-end designs: v1, which was fabricated, and v2, which is the redesign.
Neither board has been used to record people yet. This project asks what each board would let a decoder do.

The method runs **real multi-day surface EMG** through a sample-level emulation of each board's signal chain. It then trains the same decoders on what comes out.

Every number in [`results/summary.md`](results/summary.md) is regenerated by `make all`.

Two things were fixed during this work and should be visible to a reviewer:
- **Hum model.** A first version drew the hum level per recording. Because each recording holds one class, that made hum a class fingerprint, and within-day accuracy for v1 rose to an impossible 93–95%. Hum level is now drawn per day.
- **Duplicate days.** An early run kept the duplicated days (see Data). They are now dropped.

## Results

All numbers are balanced accuracy over 11 classes, where chance is 9.1%. They come from one subject: trained on days ≤ 60, tested on 57 later days. Full tables are in [`results/summary.md`](results/summary.md).

**v2 passes through essentially everything a decoder needs.**
- Cross-day LDA scores 87.3%, against 87.9% for the same recordings with no board at all.
- 100 mV of 60 Hz common-mode costs 0.2 points; 1 V costs 3 points.
- Electrode impedance from 0 to 50 kΩ makes no measurable difference.

**v1 cannot support gesture decoding.**
- At 20 kΩ electrodes it scores 30.8% with C9/R15 fitted and 22.3% with them empty.
- With 100 mV of hum it drops to 13–14%, close to chance.
- The sweeps separate two causes:
  1. **Unbuffered 1k inputs.** Electrode impedance divides the difference-amp gain from 47 to 2.45 and CMRR from 62 to 23 dB. Only 0.22% of samples ever clear the SS14's 0.4 V.
  2. **Rectification itself.** Even with ideal buffered inputs, v1 reaches only 59.5% (envelope) or 71.4% (rectified), 16–28 points below v2.

**Evaluation protocol changes the number more than the model does.**
- A shuffled window split reports 91.3%; the honest cross-day number is 87.3%.
- An LDA trained on 5 days drops from about 90% on the next few days to about 81% after 3–4 months.
- On identical test windows, 2 s per class of same-day data alone (77.5%) matches 58 days of older data (77.5%). Simply pooling the two doesn't help, because 2 s is swamped by 58 days. Weighted or adaptive recalibration is the next step.

**The CNN failure was a data problem, and fixing it for the right reason recovered it.**
- The plain CNN validated at 92.5% on days 51–60 but scored 68.2% on the test days.
- LDA trained on the *identical* windows scored 86.8%, so the gap wasn't a data-quantity problem.
- Per-day accuracy showed a cliff, not drift. Per-channel skewness traced it to electrode polarity changes: from day 69 on, every test day has a lead-polarity pattern absent from training.
- Random polarity augmentation lifted the CNN to 86.3%, matching LDA.
- Gain augmentation, the textbook fix for electrode drift, made it *worse* (60.6%). Normalising by a daily reference recording also did nothing (±0.3 points). This subject's day-to-day change was not gain.


## Data

**Dataset.** [LibEMG MultiDay](https://github.com/LibEMG/MultiDay) (Kaufmann, Englehart & Platzner, IEEE EMBC 2010):
- 1 subject, 121 recording days.
- 4 bipolar surface-EMG channels at 2048 Hz.
- 11 wrist and hand classes.
- One sustained contraction of about 6 s per class per day.

**Why this dataset.** It has the same channel count as the board. It also spans far more days than Ninapro DB6's 5.

Ninapro and PhysioNet sit behind a registration wall and were not reachable where this was built. `emgdec/data.py` is the only file that would change to run on them.

**Two problems in the published files** (`make audit`, `results/data_audit.json`). Both were found while debugging why the CNN fell apart on later test days.

- **Byte-identical days.** Days 5/7, 63/68 and 110/112 are the same files under two day numbers, all 11 classes each. All six days are excluded, leaving 115 days: 58 train (≤ 60) and 57 test (> 60).
- **Electrode polarity changes between sessions.** A channel's skewness flips sign while its RMS doesn't, which is what a reversed lead looks like. The four-channel sign pattern changes around days 26, 68 and 105 (`results/figures/polarity.png`).
  - From day 69 on, every test day has a pattern that never occurs in days 1–60.
  - Hudgins features are sign-invariant, so LDA never notices.
  - A CNN on raw waveforms does notice.
  - This is left uncorrected on purpose: a real orthosis will also get a lead clipped on backwards.

## Signal chains

The values below are read off the schematics in `openeremg.kicad_sch` and `emgcomp.kicad_sch`.

| Stage | v1 (fabricated) | v2 (redesign) |
|---|---|---|
| Input | Electrodes drive the 1k resistors of the difference amp directly | 10k series into the INA333 (100 GΩ input) |
| Stage 1 | LM324 difference amp, 1k/47k, G = 47 with ideal sources | INA333, G = 1 + 100k/11k = 10.1 |
| HPF | Sallen-Key 15k/470n, K = 1 + 10k/18k = 1.556, Q = 0.69 | same |
| LPF | Sallen-Key 1k/330n, K = 1.556, Q = 0.69 | same |
| Gain | 1 + (47k + 0–100k)/1k = 48–148 | 1 + (10k + 0–100k)/1k = 11–111 |
| Output | SS14 half-wave (0.4 V drop), then C9 10µ ∥ R15 18k (τ = 180 ms) or C9/R15 left empty | Straight to the ADC, centred on VREF = 1.65 V |
| Supply | ±3.3 V (ICL7660); the LM324 cannot swing above about +1.8 V | Single 3.3 V, rail-to-rail |
| Common-mode | Resistor matching, about 62 dB, and electrode imbalance (below) | INA333 100 dB min, plus a right-leg drive |
| ADC | ESP32-S3, 12-bit, about 10 effective bits | same |

`make board` checks the filter numbers without any data, and `tests/` pins them.

**Filter band.** The HPF+LPF cascade is −3 dB at **23 Hz and 474 Hz**, with a passband gain of ×2.41.
- The corner frequencies are 22.6 Hz and 482 Hz. Note that K = 1.556 per stage, so these are not unity-gain filters.
- The digital emulation at 2048 Hz stays within 0.4 dB of the analog circuit below 400 Hz.

**The v1 front end is loaded by the electrodes.** The 1k input resistors sit in series with the skin-electrode impedance. That impedance both divides down the gain and unbalances the bridge that sets CMRR.

| Electrode impedance | v1 stage-1 gain | v1 CMRR | Input needed to clear the SS14 at max pot |
|---|---|---|---|
| 0 (buffered) | 47 | 62 dB | 24 µV |
| 5 kΩ | 8.6 | 32 dB | 129 µV |
| 20 kΩ (default) | 2.45 | 23 dB | 456 µV |
| 50 kΩ | 0.99 | 18 dB | 1.1 mV |

The table assumes a 25% mismatch between the two electrodes. Surface EMG is typically 50 µV to 1 mV at the skin.

The v2's 100 GΩ inputs make electrode impedance irrelevant. Its effective CMRR, including the right-leg drive, is about 116 dB.

## Decoders and protocols

**Features.** Windows are 400 samples (195 ms) with a 100-sample (49 ms) step. The first 0.5 s of every recording is dropped while the filters and envelope settle.

**Models.**
- **LDA** on Hudgins features (log MAV, log WL, ZC, SSC per channel), with shrinkage.
- **1D CNN** (3 conv blocks, 37k parameters) on the windows themselves, trained on days 1–50 (non-overlapping windows). The epoch is chosen on days 51–60 and tested on days 61–121.
  - It is run plain, with random per-channel gain augmentation (×⅔–×1.5), and with random per-channel polarity augmentation.
  - An LDA trained on exactly the CNN's windows is the control.
- Both models get exactly the same board output.

**Protocols.** They are ordered from most flattering to most honest.

| Protocol | Train | Test |
|---|---|---|
| Random split | 75% of windows from days 1–60, shuffled | The other 25%. Overlapping neighbours leak, so **don't quote this one**. |
| Within-day | First 60% of each day's recordings | Last 40% of the same day, after a 0.25 s gap |
| Cross-day | Days 1–60 | Each of days 61–121, no recalibration |
| Days elapsed | 5 consecutive days | Every later day, binned by days since training |
| Recalibration | Days 1–60 plus k s per class from the test day (or those k s alone) | Last 40% of that test day |
| Reference normalisation | Cross-day, with each day's amplitude features divided by that day's class-0 recording | Classes 1–10 |

**Metric.** Balanced accuracy, where chance is 1/11 = 9.1%. Numbers are the mean ± SD across test days.

**Sweeps.**
- 60 Hz common-mode from 0 to 1 V on the body, per board.
- Electrode impedance from 0 to 50 kΩ, per board.

## What this does *not* show

- **One subject.** Every accuracy here is a single-subject number, not a population estimate.
- **The source recording already went through a lab amplifier.** The emulation can make it worse but never cleaner. Board noise below the NeXus amplifier's noise floor is invisible, so v2 is bounded above by the reference chain.
- **Units are taken as µV.** The dataset doesn't state them, but the amplitudes (30–300 µV RMS) are consistent with µV.
- **Polarity changes are inferred from skewness, not documented by the dataset authors.** A sign flip in skewness with unchanged RMS is the signature of a reversed lead. Another explanation, such as an amplifier configuration change, would have the same effect on the decoders.
- **Class 0 may not be rest.** LibEMG labels it "no motion", but it has the *highest* amplitude of the 11 classes on every day. The labels are used as given, and nothing here relies on class 0 being rest.
- **The electrode impedance model is an assumption.** It is resistive, 20 kΩ ± 25% by default. The sweep shows how much the v1 result depends on it. The v1 inputs being unbuffered is not an assumption; it is on the schematic.
- **Other analog assumptions.**
  - INA333 CMRR 100 dB (datasheet minimum), right-leg drive worth 20 dB, 3 pF common-mode input capacitance.
  - The ESP32-S3 ADC is treated as linear. The real one needs `esp_adc_cal`.
  - Op-amp offsets and noise are ignored.
  - The v2's 4.8 kHz anti-alias RC sits above this emulation's Nyquist and is not modelled.
- **v1 with C9/R15 empty is modelled optimistically.** It assumes the ADC discharges the node every sample; on the real board the node floats.
- **Sustained contractions only.** There are no transitions, no motion artefact, no real-time loop and no latency measurement.

## Layout

```
emgdec/board.py       v1 and v2 signal chains, pot calibration, hum model
emgdec/data.py        MultiDay loader (+ .npz cache), duplicate days excluded
emgdec/features.py    windowing, Hudgins features
emgdec/models.py      LDA pipeline, EMGNet CNN, training loop
emgdec/pipeline.py    recordings -> board -> feature table
emgdec/protocols.py   the evaluation protocols above
scripts/              audit_data, verify_board, run_lda, run_cnn, lda_control, report, get_data.sh
tests/                filter corners, v1 dead zone and loading, v2 linearity, features
results/              data_audit.json, board.json, lda.json, cnn.json, lda_control.json, summary.md, figures/
```

## Reproduce

```
make setup   # numpy scipy scikit-learn numba torch matplotlib pytest
make data    # ~2 GB git clone
make all     # tests, board check, LDA (~30 min), CNN (~20 min on 4 CPU cores), report
```
